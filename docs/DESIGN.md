# Sana — интерфейс рабочего продукта

## Назначение

Пользователь должен понять следующий шаг, увидеть пользу AI и закончить действие. Главная визуальная особенность — сопоставление текста задачи с конкретными вопросами и объяснением рейтинга.

## Визуальные правила

- Светлая рабочая область, белые поверхности, тёмный читаемый текст и один синий акцент действия.
- Постоянная навигация: каталог, редактор, мои задачи. Одинаковые названия действий на всём пути.
- Одна главная кнопка на текущем этапе. Фильтры и вторичные действия визуально подчинены ей.
- Текст вопросов и карточек — основное содержимое; баллы помогают принять решение и не заменяют объяснения.
- Одинаковые отступы, высоты полей, размеры подписей и состояния кнопок.
- Короткие понятные сообщения об ошибках рядом с действием, видимый фокус клавиатуры, нормальный перенос длинных слов.
- Русский, казахский и английский интерфейс; названия задач и пользовательский текст сохраняют исходный язык.
- Нативные элементы управления, проверка на узком экране и ноутбуке; анимация только для обратной связи.

## Финальная рабочая версия интерфейса

Направление — компактный каталог открытых задач, по принципу рабочих каталогов соревнований Kaggle, с собственной идентичностью Sana. Это не рекламный лендинг: в первом экране важны доступные задачи, критерии выбора и одно основное действие. Логотип, тексты и материалы Kaggle не копируются.

- Палитра: Ink `#172b45`, Sana Blue `#2559dc`, Workspace `#f4f6fa`, Surface `#ffffff`, Border `#dce4ef`, Ready Green `#23835e`. Цвет готовности всегда сопровождается словом и числом.
- Типографика: локальные Segoe UI Variable / Segoe UI и системные запасные шрифты. Никаких сетевых шрифтов; кириллица и казахские символы не зависят от CDN. Заголовки 27–32 px, текст форм 14–16 px, объяснения оценки не мельче 12 px.
- Каталог: две равнозначные колонки на настольном экране, одна на узком. Первая задача не занимает всю строку. Приоритет в карточке: проблема → ожидаемый результат → отклики; рейтинг виден отдельно и не заменяет текст.
- Обзор готовности показывает только реальные количества опубликованных задач в четырёх диапазонах. Ссылки используют существующие URL-фильтры. Низкие оценки и учебные примеры не скрываются.
- Конструктор: выраженные три этапа, спокойная форма ввода, отдельная область анализа; основания баллов открываются отдельно от основных полей. Согласие на публикацию заметно и остаётся ручным.
- Доступность: видимый фокус, обычные ссылки для фильтров, различимые состояния, сохранённые подписи всех полей, отсутствие декоративной анимации и учёт reduced motion. На узком экране ввод 16 px предотвращает принудительное увеличение формы в мобильных браузерах.

Новые компоненты не меняют серверные API, правила рейтинга, владельцев задач, сохранение черновиков или обязательные подтверждения. Систему шрифтов, цвета и плотность выбирали по Frontend Design; формы, навигацию, длинный текст и фокус проверяли по Web Interface Guidelines.
