# Рейтинг готовности бизнес-задачи

Рейтинг показывает, насколько подробно описана конкретная задача для работы со студенческой командой. Он не оценивает известность компании, сложность идеи, чувствительные признаки участников или качество команды. Все опубликованные задачи доступны для откликов при любом рейтинге.

Эта рубрика относится к новой версии React + FastAPI. Источник формулы — `agent/architect_tools.py`, функция `score_card_fields`.

## Семь критериев

| Критерий | Вес | Поля карточки | Что означает уровень 4 |
|---|---:|---|---|
| Контекст и потребность | 20 | `context`, `need` | Понятны существующий процесс, конкретная проблема и желаемое изменение |
| Данные и материалы | 20 | `data` | Названы источник/материалы, формат или пример, доступность и способ передачи; обоснованное отсутствие потребности в данных допустимо |
| Ожидаемый результат | 15 | `expected_result` | Указано, что команда передаст, что результат должен делать и где заканчивается объём работ |
| Критерии успеха | 15 | `success_criteria` | Описаны наблюдаемые условия приёмки и способ проверки; допустим качественный тест, если он подходит задаче |
| Ограничения | 10 | `constraints` | Конкретны применимые сроки, объём, доступ, расходы или требования к данным; явное отсутствие ограничения — тоже информация |
| Пользователи | 10 | `users` | Названы группа пользователей и действие, которое им нужно выполнять |
| Связь с бизнесом | 10 | `contact`, `interaction_format` | Есть рабочий контакт и согласованный формат/периодичность обратной связи |
| **Всего** | **100** | | |

Название `title` необходимо для понятной публикации, но отдельные баллы за него не начисляются.

## Качественные уровни и арифметика

| Уровень | Значение |
|---|---|
| 0 | Сведения отсутствуют, неизвестны, противоречат друг другу или не относятся к критерию |
| 1 | Есть упоминание, но оно слишком общее для действий команды |
| 2 | Есть полезная конкретика, но остаётся существенный практический пробел |
| 3 | Можно действовать; нужно небольшое уточнение |
| 4 | Достаточно сведений для начала работы и проверки результата по этому критерию |

Для каждого критерия:

```text
баллы = floor(вес × уровень / 4 + 0.5)
итог  = сумма баллов семи критериев
```

Код использует целочисленную формулу `(weight * level + 2) // 4`, то есть округление половины вверх. Вес 15 и уровень 3 дают 11 баллов; вес 10 и уровень 1 дают 3. При всех уровнях 4 итог равен 100.

Число символов и наличие «правильных слов» сами по себе не приносят баллы. Короткий точный ответ может получить высокий уровень; длинный общий текст — низкий. В актуальном AI-режиме модель оценивает фиксированные требования, а Python выводит уровень и баллы, не позволяя модели менять веса.

### Проверяемые требования внутри критериев

Всего 13 требований: ситуация и изменение; материалы и доступ; передаваемый результат и его назначение; условие приёмки и способ проверки; ограничения; группа пользователей и её действие; канал связи и обратная связь. Модель указывает состояние и идентификаторы исходных фрагментов для каждого. `missing` не имеет доказательств; остальные состояния требуют проверяемых идентификаторов.

Python выводит уровень: все `met` → 4; `met` вместе с `partial`, без отсутствующих → 3; есть `met` и `missing` → 2; только неопределённые `partial` с возможными отсутствующими → 1; все `missing` либо любой `blocked` → 0. Затем действуют ограничения составных полей и статуса пригодности. Полная оценка не требует численного KPI, если для задачи достаточна конкретная качественная приёмка.

Для составных критериев нужны оба поля. Если заполнена только одна часть `context/need` или `contact/interaction_format`, уровень ограничивается 2. Один фрагмент может содержать сразу контекст и потребность: повтор цитаты сам по себе не снижает баллы, её смысл оценивает AI. Пустое поле или явная заглушка вроде «не знаю», `unknown`, «білмеймін» не считаются содержательной информацией.

## Доказательства и подтверждение

AI возвращает по каждому критерию ключ, статус пригодности и оценки фиксированных требований. Python выводит уровень, собирает причину из наблюдений и выбирает следующий шаг по главному пробелу; при полной оценке просит подтвердить сведения. Цитаты берутся из соответствующих проверенных полей карточки. Модель классифицирует исходные фрагменты по идентификаторам; Python строит поля из оригинального текста. Фрагмент черновика или ответа может поддерживать несколько полей. Явный ответ для своего поля имеет приоритет, включая намеренную очистку. Неизвестные факты не дописываются.

Непригодные статусы (`missing`, `unknown`, `irrelevant`, `contradictory`, `unverifiable`) и отсутствие самой задачи обнуляют критерий в коде. Определение статуса зависит от модели: механизм не гарантирует распознавание всех противоречий. В последнем целевом тесте недоступные до дедлайна данные получили ноль, но обнаружены неправильное поле для срока и завышенный балл за подразумеваемую приёмку. Подробности — в [результатах проверок](VALIDATION.md).

До ручного подтверждения показывается **предварительный** рейтинг: он позволяет сравнить исходное описание и уточнённый вариант, но не является опубликованным результатом. API публикации и сохранения изменений требует `confirmed: true`; баллы из браузера и произвольные AI-review сервер не принимает.

`analysis_id` связывает карточку с проверенным результатом в SQLite и браузером автора. При совпадении полей с сохранённым анализом сервер применяет доверенную оценку. Если поля изменились, прежние уровни больше не используются: нужен повторный AI-анализ либо честная локальная оценка. Сохранение без изменения полей не снижает уже подтверждённый рейтинг.

В ответе API указаны:

- `score_source: "ai"` — использован проверенный AI-анализ соответствующих полей;
- `score_source: "local"` — консервативная локальная проверка наличия информации;
- `score_source: "sample"` — учебная карточка с вручную подготовленной оценкой;
- `analysis_fields_changed: true` — карточка изменена после прежней проверки; нужна повторная оценка смысла.

Цитаты подтверждают происхождение текста, а не достоверность сведений в жизни. Человек отвечает за подтверждение собственных фактов. Качество смысловой оценки и вопросов требует отдельных проверок; строгий JSON сам по себе его не гарантирует.

## Локальная проверка и учебные примеры

Без смыслового AI-review непустой критерий получает только уровень 1, пустой — 0. Максимальная сумма равна **27**, а не 100. Локальный режим запускается явно и не выдаётся за AI. Сбой внешнего API сам по себе не заменяет результат заранее подготовленным ответом.

`data/seed_reviews.json` содержит подготовленные человеком оценки пяти синтетических карточек. Все положительные оценки привязаны к цитатам из соответствующих полей. Сервер использует ту же арифметику: `t1=93`, `t2=81`, `t3=89`, `t4=23`, `t5=43`. Это демонстрационные оценки, не текущие результаты OpenAI.

## Уровни готовности и каталог

| Баллы | Уровень |
|---|---|
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Каталог сортируется по убыванию рейтинга. Фильтры позволяют выбрать тему и готовность; низкий рейтинг не скрывает задачу и не запрещает предложение. Подтверждённые изменения пересчитываются сервером. `max_points` у вопроса — оставшийся максимум критерия, а не обещание автоматически начислить столько баллов за любой ответ.

Баллы команды за выполненный этап — отдельный показатель. Они не повышают рейтинг задачи. Автор выбирает команду, проверяет результат и вручную подтверждает один этап на предложение; команда получает +10 ровно один раз.

## Проверка и первая версия

`tests/test_architect.py` проверяет извлечение фактов, критерии, вопросы и арифметику. `tests/test_api.py` проверяет подтверждение, недоверие к клиентским баллам, происхождение рейтинга, сохранение и защиту от повторных начислений. `data/evaluation_cases.json` и `scripts/evaluate_architect.py` предназначены для отдельной проверки качества вопросов и смысловых уровней на разных задачах.

Сохранённая Streamlit-версия использует `rating.py`: контакт и формат взаимодействия разделены на две строки по 5 баллов и есть эвристические ограничения. Старая реализация не вызывается новым API. Для оценки актуального продукта используйте семь критериев из `agent/architect_tools.py` и запуск FastAPI по README.
