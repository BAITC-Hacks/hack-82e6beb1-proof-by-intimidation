# Соответствие кейсу и технической рубрике

Матрица для жюри, а не самостоятельно присвоенные баллы. Требование считается проверенным только в пределах указанного теста. Содержание исходного кейса сохранено дословно в `AGENTS.md`.

Статус checkpoint 23.09.2026: функциональные переходы проверены; качество смысловой оценки AI — частично. В живых трёх сценариях выполнены 137/138 автоматических проверок; оставшаяся ошибка — распределение известного документа по полям. Найдены также ошибочные пояснения оценки и частичные баллы за недоступные в срок данные. Это не заявление о полном выполнении всех качественных требований или гарантированных баллах жюри. Подробности — `VALIDATION.md` и `LIVE_EVAL.md`.

## Обязательные функции

| Требование | Реализация и проверяемое свидетельство |
|---|---|
| Свободный черновик → минимум три уместных вопроса | `agent/architect.py`; `test_grounded_contract_and_question_points`, `test_duplicate_questions_are_rejected`; релевантность отдельно оценивается живым AI, см. `LIVE_EVAL.md` |
| Десять редактируемых полей, без выдуманных фактов | `agent/evidence.py`, `frontend/src/App.jsx`; тесты выдуманных цитат, нескольких фрагментов, явно очищенных ответов; `evaluate_workflows.py` проверяет сохранение всех ответов |
| Человек подтверждает перед публикацией | `ChallengeInput.confirmed`, форма конструктора; `test_unconfirmed_cards_and_client_scores_are_rejected`, полный сценарий |
| Рейтинг 0–100, расшифровка, недостающее, пересчёт | Семь критериев 20/20/15/15/10/10/10; `test_full_validated_criteria_total_100`, `test_edit_recalculates_and_rejects_stale_version`; UI помечает устаревший анализ |
| Все задачи в общем каталоге, рейтинг, фильтры темы/готовности | `catalog_view` и UI каталога; `test_seed_catalog_is_complete_sorted_and_read_only`; фильтры требуют браузерной проверки |
| Низкий рейтинг не скрывает задачу и не запрещает отклик | `test_low_rating_tasks_accept_unlimited_proposals`; нет порога рейтинга или лимита числа предложений в обработчике |
| Идея, план и ссылка на прототип в предложении любой команды | `ProposalInput`; три независимые команды в каждом `evaluate_workflows.py` сценарии; проверка некорректных URL |
| Бизнес вручную выбирает одну, несколько или ни одной команды | `test_full_manual_journey_and_once_only_progress`, `test_owner_can_reject_all_teams_without_assignment`; два выбора и один отказ в acceptance-сценариях; другого владельца API не допускает |
| Баллы только за подтверждённый этап выбранной команды | `test_concurrent_milestones_award_exactly_ten`; попытки до выбора и повторного начисления в acceptance-сценариях |
| Содержательный реальный AI, честный режим ошибки/офлайн | Реальные вызовы Responses API и инструментов; `test_missing_ai_is_a_clear_error_not_silent_canned_answer`; `--live` никогда не переключается молча в офлайн |
| AI не назначает команды и не использует чувствительные признаки | Инструменты агента работают с описанием задачи и рубрикой; решений о командах среди них нет. Предложения и демографические признаки не передаются AI |
| Минимум пять черновиков, карточек, команд, предложений | Четыре seed-файла в `data/`; `test_every_demo_draft_has_editable_seed_card`, начальная загрузка API |
| README: архитектура, формула, каталог, запуск, тесты | Соответствующие разделы русского `README.md`; Windows и Linux/macOS команды. Фактически проверенные платформы указаны в `VALIDATION.md` |
| Демонстрация до пяти минут | Сценарий с таймингом в README; наличие сценария не заменяет успешный показ и репетицию с секундомером |

## Воспроизводимый сквозной прогон

`data/acceptance_cases.json` содержит три новых синтетических задачи: ремонт проекторов, разбор ошибок эссе на казахском и инструкция для волонтёров архива. Последняя задача намеренно не требует нового приложения; критерии допускают качественную наблюдаемую приёмку.

Из корня установленного проекта, интерпретатором `.venv`:

```text
python scripts/evaluate_workflows.py
python scripts/evaluate_workflows.py --live --output .qa/workflow-live.json
```

На Windows замените `python` на `.\.venv\Scripts\python.exe`, на Linux/macOS — на `.venv/bin/python`. По умолчанию API-кредиты не тратятся. `--live` запускает два оплачиваемых анализа на сценарий. Скрипт создаёт отдельную SQLite внутри игнорируемой `.qa/`, не меняет рабочую базу и браузер. JSON содержит синтетические входы, проверки и время; это не браузерный тест и не статистически репрезентативная оценка AI.

## Техническая рубрика — пределы доказательств

| Критерий | Что проверять | Что тестами нельзя обещать |
|---|---|---|
| Соответствие кейсу, 20 | Матрица функций и полный живой сценарий | Дополнительные функции не компенсируют обязательную сломанную |
| Реализация, 25 | Связанные UI/API/SQLite/реальный агент; серверная формула и права | Прохождение мок-тестов само по себе не доказывает качество AI |
| README, 20 | Архитектура, установка, сценарий, ограничения и раскрытие материалов | Документация не заменяет работающий запуск |
| Воспроизводимость, 20 | Чистые зависимости, новая БД, сборка и HTTP-проверки | Локальная копия не равна проверенному деплою или испытанию всех ОС |
| Надёжность и безопасность, 15 | Права, приватность, конфликты, сохранность, очередь, невалидный ввод | Cookie — не полноценная аутентификация; маленький benchmark — не нагрузочный аудит |

Процедурные условия организаторов проверяются отдельно: репозиторий платформы, своевременный push до блокировки, личные коммиты каждого участника, почасовой прогресс и реальная защита. Приложение не может автоматически доказать выполнение этих условий.
