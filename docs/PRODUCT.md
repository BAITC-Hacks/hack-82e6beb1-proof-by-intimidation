# AI Sana Challenge Hub — продукт и критерии приёмки

Бизнесу нужно объяснить задачу так, чтобы студенческая команда могла оценить работу и предложить решение. Команде нужно понять проблему, доступные данные, ограничения и способ приёмки. Продукт соединяет эти действия в один проверяемый сценарий.

## Пользовательский путь

Черновик → предметные вопросы AI → ответы и редактируемая карточка → ручное подтверждение → прозрачный рейтинг → открытый каталог → предложение команды → решение бизнеса → подтверждённый этап и баллы.

## Главные экраны

- Каталог: доступные задачи, фильтры, поиск, рейтинг и данные, достаточные для выбора. Низкий рейтинг не блокирует отклик.
- Редактор: исходный текст, вопросы с причиной, ответы, редактируемая карточка, основания рейтинга. Предварительная оценка отделена от подтверждённой.
- Мои задачи: опубликованные задачи владельца, сравнение предложений, ручное решение, подтверждение результата.

## Что считаем качеством AI

- Минимум три различных вопроса о фактах, которые влияют на работу команды.
- Вопросы и объяснения учитывают предмет конкретного черновика.
- Поля карточки извлекаются из текста и ответов. Неизвестные сведения остаются пустыми.
- Каждая положительная оценка AI имеет проверяемую цитату из соответствующего поля.
- Формула баллов детерминирована; модель не может менять веса, публиковать задачу или выбирать команду.
- Ошибка API остаётся ошибкой с возможностью повторить запрос. Локальный режим включается явно и подписан.
- Данные, критерии и ограничения нельзя заменить общими фразами ради максимального рейтинга.

## Приёмка

1. Пройти весь путь от нового черновика до баллов за этап.
2. Проверить, что обновление страницы сохраняет опубликованную задачу и отклики.
3. Проверить запрет изменения чужой задачи и повторного начисления баллов за один этап.
4. Проверить русский, казахский и английский ввод; пустой, чрезмерно длинный и бессодержательный ввод.
5. Выполнить тесты и запуск из чистой среды по README.

## Границы MVP

SQLite и анонимная сессия владельца позволяют проверить сценарий без внешних сервисов. Это не аккаунты, восстановление доступа или готовая инфраструктура для публичного запуска. Демо-профили и карточки синтетические.
