# Проверка реального AI-анализа

Проверено 23 сентября 2026 года. Это отчёт о наблюдавшихся запусках, а не обещание одинаковых оценок при каждом запросе и не замена экспертной оценке качества вопросов.

## Условия

- Использован настоящий OpenAI Responses API, модель `gpt-4.1`, без подмены ответов заготовками.
- Для сравнения с исходным `gpt-4o-mini` модель временно задавалась переменной окружения процесса. Файл с ключом во время этих проверок не редактировался.
- Модель выбирала инструменты из четырёх доступных: критерии рейтинга, проверка цитат, расчёт баллов, сравнение редакций. В успешных запусках использованы критерии и проверка цитат, обычно также расчёт баллов.
- Предел одного анализа: четыре запроса основного цикла, до шести вызовов инструментов и не более одного дополнительного исправления невалидного итогового ответа. Повторная неудача возвращает явную ошибку, а не выдаёт локальный шаблон за AI.
- Все оценки до подтверждения человеком являются предварительными.

## Обнаруженные недостатки и исправления

1. `gpt-4o-mini` выдавал смешанный русский/английский текст, пропускал уже названных пользователей и иногда обходил инструменты. Добавлены проверки языка и обязательный выбор моделью полезных инструментов. По наблюдавшимся примерам `gpt-4.1` лучше сохранял известные факты и задавал более предметные вопросы.
2. Модель повторно переписывала цитаты с добавленными кавычками. Теперь Python строит итоговую карту источников и доказательства рейтинга из уже проверенных дословных полей; модель оценивает их смысловую полноту. Выдуманные фактические поля по-прежнему отклоняются.
3. Пустые цитаты незаполненных полей ошибочно считались выдуманными фактами. Они теперь обозначают отсутствие утверждения. Непустые цитаты проверяются по настоящему исходнику, который передаёт сервер.
4. При первом казахском запуске модель упомянула нестабильный интернет в резюме, но пропустила его в ограничениях. Уточнено правило извлечения условий работы; в оценочный набор добавлена отдельная проверка сохранения явных фактов в правильных полях. Повторный запуск прошёл эту проверку.
5. Явно очищенное пользователем поле могло восстанавливаться из черновика. Теперь наличие ключа ответа имеет приоритет даже при значении `""`; добавлены регрессионные тесты для AI-валидации и офлайн-режима.

## Ограничения качества

- Некоторые вопросы об ожидаемом результате или критериях успеха остаются широкими. Разница между предметными областями проверена, но качество всех формулировок не гарантировано.
- В одном полном библиотечном примере модель предложила уточнить продление уже заданного срока. Инструкция дополнена требованием уважать согласованные сроки и границы; отдельного повторного полного прогона после этого изменения не было.
- Модель может по-разному оценить степень конкретности одного поля. Детерминированная формула гарантирует арифметику, но не превращает семантическое суждение модели в объективную истину.
- Три языка проверены на небольшом числе живых примеров. Носитель казахского языка не выполнял редакторскую проверку; отдельные формулировки могут быть неестественными.
- Прохождение автоматических проверок подтверждает структуру, источник фактов и несколько конкретных требований. Оно не доказывает отсутствие всех смысловых ошибок. Например, пропущенное ограничение было обнаружено ручным просмотром, после чего добавлено в автоматическую проверку.
- Все 12 примеров проверялись в явно обозначенном офлайн-режиме на контракт данных; полный платный прогон всех 12 с `gpt-4.1` не выполнялся. Офлайн-проверка не считается доказательством качества AI.

## Как повторить

После установки зависимостей задайте `OPENAI_API_KEY` и `OPENAI_MODEL=gpt-4.1` в локальном окружении. Ключ не передавайте в командной строке и не коммитьте.

```text
python -m pytest tests/test_architect.py -q
python scripts/evaluate_architect.py
python scripts/evaluate_architect.py --live --case dean_ru
python scripts/evaluate_architect.py --live --case library_ru --with-answers
python scripts/evaluate_architect.py --live --case village_school_kk --case cafeteria_en --case injection_ru
```

`--live` расходует API-кредиты. Без него вызывается только явно обозначенный офлайн-режим. Скрипт печатает JSON с вопросами, расшифровкой оценки, пройденными проверками и пунктами для ручной оценки. `--debug-validation` показывает только локальную причину отказа валидации; данные ответа провайдера и ключ не выводятся.

Автономный набор AI-тестов: **32 теста прошли**. Проверяются выдуманные и чужие источники, сохранение ответа человека, очистка полей, ошибки ввода, отсутствие скрытого офлайн-перехода, обработка одного исправления, пределы и арифметика рейтинга, проверка инструментального цикла и ограниченный журнал входных параметров. Журнал содержит краткий результат и не более 1 200 символов входных аргументов с явной отметкой усечения; значения, похожие на API-ключ, маскируются.

Реализация опирается на официальные описания [function calling](https://developers.openai.com/api/docs/guides/function-calling), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1).
